# macOS-клиент ZAPRET CONTROL

## Важно: полной версии zapret для macOS не существует

`winws.exe` использует драйвер **WinDivert** и платформу Windows Filtering
Platform. В macOS их нет, поэтому сам обход DPI на Mac этим проектом
не запускается — ни через EXE, ни через Mono/Wine.

Этот клиент делает другую полезную вещь: **направляет трафик Mac через
LAN-прокси Windows-ПК**, на котором zapret уже работает. Прокси поднимается
скриптом `proxy\start-all.bat` или панелью ZAPRET CONTROL (вкладка «Прокси»):
HTTP `:8080`, SOCKS5 `:1080`.

```
Mac (этот скрипт) ──► Windows-ПК :8080/:1080 ──► winws (zapret) ──► интернет
```

## Подготовка

1. На Windows-ПК запусти `proxy\start-all.bat` (или установщик
   `ZapretControlSetup.exe`) и убедись, что прокси слушает порты 8080/1080
   и работает выбранная стратегия.
2. Узнай IP этого ПК в локальной сети — он показан на вкладке «Прокси»
   в ZAPRET CONTROL или командой `ipconfig` (IPv4 адрес).
3. Mac и ПК должны быть в одной Wi-Fi/ Ethernet-сети. rules брандмауэра
   `start-all.bat` уже разрешают локальные подсети.

## Использование

```bash
cd macos
chmod +x zapret-proxy.command
./zapret-proxy.command
```

Откроется меню:

1. **Указать IP Windows-ПК и включить прокси** — адрес сохраняется в
   `~/Library/Application Support/ZapretControl/proxy.conf`.
2. **Выключить прокси** — возвращает системные настройки в исходное состояние.
3. **Показать статус** — данные `networksetup` по HTTP/HTTPS/SOCKS5.
4. **Проверить связь через прокси** — запросы к example.com и YouTube
   через `http://<ПК>:8080` (код 200 и 204 = норма).
5. **Выбрать сетевое подключение** — Wi-Fi, Ethernet, Thunderbolt и т.д.

`networksetup` требует прав root, поэтому при интерактивном запуске скрипт
сам перезапускается через `sudo` и запрашивает пароль администратора Mac.
Локальные адреса (`localhost`, `192.168.*`, `10.*`, `*.local`) идут напрямую.

### Режим для скриптов

```bash
./zapret-proxy.command --on 192.168.1.10          # включить
./zapret-proxy.command --on 192.168.1.10 --service "Ethernet"
./zapret-proxy.command --status                   # статус
./zapret-proxy.command --test                     # проверить связь
./zapret-proxy.command --off                      # выключить
```

## Вручную (без скрипта)

Системные настройки → Сеть → Wi-Fi → Подробности → Прокси:

* веб-прокси HTTP и защищённый веб-прокси HTTPS: `IP_Windows_PK`, порт `8080`;
* прокси SOCKS5: `IP_Windows_PK`, порт `1080`;
* «Исключить простые хосты»: `localhost,127.0.0.1,*.local,192.168.*,10.*`.

## Ограничения и диагностика

* Системный прокси читают не все приложения (например, игры и часть CLI
  могут игнорировать настройки macOS). Для них нужна настройка внутри
  самого приложения или SOCKS5-клиент.
* Если `--test` не отвечает: проверь, что на ПК запущен прокси (нет
  `proxy\proxy.disabled`), порт 8080 открыт, IP указан верно и Mac находится
  в той же подсети.
* SKype/FaceTime и часть сервисов Apple могут ходить напрямую — это
  особенность их сетевого стека, а не прокси.
* Удаление настроек: `./zapret-proxy.command --off`, файл конфигурации
  можно просто удалить.

Скрипт не устанавливает и не запускает zapret на Mac, не требует Python
и не изменяет системные файлы помимо настроек прокси выбранного подключения.
